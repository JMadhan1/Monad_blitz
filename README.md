# ZK Spend Auth — Monad Blitz Bangalore V5

**A hidden spend limit for AI agent payments, verified on-chain with a Groth16 proof.**

## The problem

AI agents are starting to pay for things autonomously (x402, agentic payment rails). Today, nothing checks whether an agent's spend request is actually authorized before the payment settles — and if you *do* add a spend limit, the naive way to enforce it puts the limit on-chain in plaintext, leaking your agent's budget to anyone watching.

## What this does

An agent's owner commits a **hash** of the agent's spend policy on-chain: `Poseidon(secretKey, maxLimit, ownerAddress)`. The real limit never appears on-chain — only its hash.

Before a payment, the agent generates a Groth16 zero-knowledge proof that the requested amount is within its committed (but hidden) limit, and submits that proof on-chain. The contract verifies the proof and marks the request `Passed` or reverts.

An over-limit request can't even produce a proof — the circuit's constraint (`requestedAmount <= maxLimit`) has no satisfying witness, so it's rejected before it ever reaches the chain.

## How it works

- `circuits/spend_auth.circom` — a small Circom circuit (Poseidon commitment check + a `LessEqThan` comparator)
- `contracts/Groth16Verifier.sol` — generated by `snarkjs`, verifies the proof on-chain using Monad's native BN254 pairing precompiles
- `contracts/ZKSpendAuth.sol` — the registry: `registerPolicy`, `validationRequest`, `validationResponse`
- `contracts/mocks/MockIdentityRegistry.sol` — a minimal stand-in for an ERC-8004-style agent identity registry
- `public/` — a static web frontend that connects a wallet, generates the ZK proof **in the browser** (via `snarkjs` + the compiled `.wasm`/`.zkey`), and submits it on-chain live

## Run it yourself

Requirements: Node.js 18+, a MetaMask-compatible wallet, some Monad testnet MON ([faucet](https://faucet.monad.xyz)).

```bash
git clone <YOUR_REPO_URL>
cd <REPO_NAME>
npm install
```

### 1. Compile the circuit (already compiled and committed under `circuits/build/`, but if you want to rebuild it)

```bash
./circom.exe circuits/spend_auth.circom --r1cs --wasm --sym -o circuits/build -l node_modules
```

### 2. Deploy to Monad Testnet

Create a `.env` file:

```
DEPLOYER_PRIVATE_KEY=0x...
```

Then:

```bash
npx hardhat run scripts/deploy.js --network monadTestnet
```

This writes `deployment.json` to the project root **and** to `public/deployment.json` (so the frontend picks up the fresh addresses automatically).

### 3. Verify the contract

```bash
npx hardhat verify <ZKSpendAuth_ADDRESS> <VERIFIER_ADDRESS> <IDENTITY_REGISTRY_ADDRESS> --network monadTestnet
```

### 4. Run the frontend

The frontend is a static site (no build step) — serve `public/` with any static host, or locally:

```bash
npx serve public
```

Open it, connect a wallet (MetaMask will prompt to add Monad Testnet if it's not already added), and:
1. Click **"Register agent + commit policy"** — commits `Poseidon(secretKey, 1000, yourAddress)` on-chain. The `1000` never appears on-chain, only its hash.
2. Click **"Spend 500 (within hidden limit)"** — generates a proof in your browser and submits it on-chain. Should pass.
3. Click **"Spend 5000 (over hidden limit)"** — the circuit has no valid witness for this, so no proof can even be generated. Blocked before it reaches the chain.

### 5. Deploy the frontend

```bash
npm install -g vercel
vercel public --prod
```

## Tech stack

Circom 2 + snarkjs (Groth16, BN254), Solidity 0.8.24, Hardhat, ethers.js v6, vanilla JS/HTML/CSS frontend (no framework, no build step — keeps the whole thing runnable by anyone with zero setup friction).
